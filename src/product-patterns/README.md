# Product patterns: share modal

Docs and Drive have no Storybook, so their encryption states of the share dialog are reproduced here for design work, under "Product patterns/Share modal". Each story is one state, "Overview" lays them all out on one page (and "Overview French" forces the French texts), and every story's `play()` asserts the element that sets its state apart. The texts are the products' own (Docs `src/frontend/apps/impress/src/i18n/translations.json`, Drive `src/frontend/apps/drive/src/features/i18n/translations.json`), copied into `strings.ts` for the Storybook `locale` global; where a product has no French entry, the French story shows the English text, as the product does.

The two products compose the dialog differently, and the stories keep that difference. Drive uses the design system's `ShareModal` (`explorer/components/modals/share/ItemShareModal.tsx`) and puts encryption only in the slots it leaves: `outsideSearchContent` for the pending section, the top of a member's role menu for "Verify identity". Docs does not use `ShareModal`: `doc-share/components/DocShareModal.tsx` builds its own dialog from the same parts (`Modal`, `QuickSearch`, one row per person), which lets it put a status next to a name, make the avatar a button and add a hint under the search results. `docs/DocsShareDialog.tsx` mirrors that with the design system's exported parts, `drive/DriveShareModal.tsx` uses `ShareModal` itself.

Trust states of a recipient's key (unknown, verified, changed, refused) never appear in either product's dialog: the vault checks them when the document key is wrapped for someone (Invite, Accept, automatic accept), and the SDK then opens the encryption interface's own overlay over the product. Those screens are in "Preview/Modals/VerifyRecipients" (unknown, mismatch, refused) and "Preview/Pages/RecipientProfile" (what the avatar or "Verify identity" opens).
